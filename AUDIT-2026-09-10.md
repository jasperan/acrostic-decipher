## Full Review Findings

Ranked by impact (read-only; no changes made):

1. **No test suite and no CI (Medium).** `uv run pytest -q` → `no tests ran`. The core matcher in
   `src/main.py:process_acrostic` has zero automated coverage; regressions in the substring-match logic would
   ship silently. Recommend adding a small pytest suite covering sentence splitting, empty-token handling, and
   the `MIN_WORD_LEN` filter.
2. **Missing explicit file encoding (Low–Medium).** `src/main.py:20` opens files in text mode without
   `encoding='utf-8'`. Under a non-UTF-8 locale, the UTF-8 dictionary can raise `UnicodeDecodeError` or
   silently misdecode; `_read_file` only catches `FileNotFoundError`, so the traceback would be unhelpful.
3. **Substring matching is inherently over-inclusive (Low).** `src/main.py:43` uses `needle in acrostic_lower`,
   so short dictionary words match inside longer acrostic strings (e.g. `ads` inside `...hadsfg`). This matches
   the documented behavior ("checks whether known English words appear"), but produces many low-signal hits.
   Design limitation, not a bug.
4. **`install_deps()` is a no-op placeholder (Low).** `install.sh:62-65` changes directory then prints a fixed
   message; the `cd` has no downstream effect. Cosmetic; left in place for output stability.
5. **Installer swallows update failures (Low).** `install.sh:47` `git pull ... 2>/dev/null || true` hides real
   errors and always reports success. Same item as the Security Findings row above.
6. **Double `rstrip()` per token (Informational).** `src/main.py:30` calls `w.rstrip()` in both the filter and
   the index expression. Negligible cost at this scale; not worth a reader-hostile rewrite.
7. **README sample output is illustrative, not literal (Informational).** The block in `README.md` shows a
   subset/abbreviation of real output; running `python src/main.py` prints the full match list. Doc drift only.
8. **Dependency hygiene is clean (Informational).** `pyproject.toml` declares no dependencies and
   `requires-python = ">=3.12"`; `uv.lock` resolves the project as a virtual package with no third-party deps;
   `.python-version` pins `3.12`. Consistent, stdlib-only.

## Remaining Risks

- **No automated tests or CI.** Correctness of the matcher is verified only by the smoke run above; any future
  change is unguarded. Highest residual risk.
- **`install.sh` was not executed end-to-end.** Running it would clone/pull from GitHub (network + mutates a
  target directory), so only syntax (`bash -n`) and a `print_banner` render check were performed. The clone,
  pull, and argument-expansion paths are unverified at runtime.
- **Locale-dependent decoding** (Finding #2) remains unaddressed by design; not fixed because it can change
  behavior on non-UTF-8 hosts.
- **`docs/wordFrequency.xlsx` (8.2 MB binary) was not content-inspected.** It is an upstream-sourced reference
  dataset; binary contents cannot be line-audited. Low likelihood of relevance to this code path.
- **`uv.lock` / dependency supply chain** was not modified or re-resolved (per instruction to never touch lock
  files); the project has zero third-party dependencies, so exposure is minimal.
